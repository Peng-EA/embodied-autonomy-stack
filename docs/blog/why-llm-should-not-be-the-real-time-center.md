# 为什么 LLM 不应成为具身智能的实时控制中心？

**—— 基于多时间尺度分层的架构假说**

> 状态：观点文章（假说） · 2026-11-05 · 作者 Peng-EA
>
> 本文不含"引用文献"式的装饰；需要外部证据的地方写明「待核实」，而不是编一个出处。

## 1. 一个被折叠掉的问题

LLM 进机器人之后，"自主"几乎被折叠成了同一件事：语义推理。

于是出现一类很常见的结构性缺陷——

- 对话很流畅，但**电量掉到 5% 还在执行长任务**；
- 能听懂"把杯子拿过来"，但**手里打滑了不会自己修正**；
- 能被要求“去充电”，但 **「没电」这件事本身从不会主动冒出来**；
- 网络抖一下，机器人**停在原地**，因为它所有决策都要等一个 HTTP 响应。

这些都不是模型能力问题，是**架构问题**：系统里没有人负责"维持自己活着"。

## 2. 时间尺度决定谁该做决策

先看一组量级（工程常识，不是论文结论）：

| 事件 | 时间尺度 | 人怎么做 |
|---|---|---|
| 关节过载、即将碰撞 | 10–100 ms | 脊髓反射，来不及"想" |
| 疼痛、饥饿、疲劳 | 100 ms–1 s | 内感受 + 情绪，驱动"想去找吃的" |
| "今天要不要去超市" | 秒–分钟 | 前额叶规划、语言 |
| "我这辈子要干什么" | 小时–年 | 叙事、价值观 |

规律很清楚：**越快的事，越不该经过慢的地方。**

LLM 有三个属性决定了它不适合做实时中心：

1. **延迟分布是长尾的**：中位数可能几百毫秒，p99 能到十几秒（重试、排队、限流）。实时控制要的是**上界**，不是中位数。
2. **它不持有稳态设定点**：模型里没有"电量 25% 以下就该充电"这种状态变量，只有 prompt 里临时写的一句话。prompt 会滚动出上下文窗口，设定点却必须一直在。
3. **它会断线**：断线不是异常，是常态（网络、额度、上游故障）。一个把决策全押在它身上的系统，断线就等于停机——**而且是在最不该停的时候停**。

## 3. 假说：四层 + 显式契约

我的假说是：把系统按时间尺度切成四层，并且**用契约规定谁能打断谁**。

| 层 | 时间尺度 | 职责 | 谁能打断它 |
|---|---|---|---|
| **L1** 内感受/稳态 | 10–100 ms | 检测设定点偏离，全局广播 | 无人（最高优先级） |
| **L2** 反射 | 10–100 ms | 避障/平衡/力控，硬否决 | L1 |
| **L3** 情感/动机 | 0.1–1 s | 情绪向量调制参数，生成目标候选 | L1 / L2 |
| **L4** 规划协调 | 1–10 s+ | 排序目标、分解任务、**异步调 LLM** | L1 / L2 |

三条关键约束：

1. **LLM 不是 L4，它是 L4 调用的外部服务。** 可插拔、可断线、结果可被抢占。
2. **抢占权归属下层。** 上层输出的永远是"建议"，下层可以在毫秒级把它废掉。
3. **情绪只调制参数，不碰安全阈值。** 恐惧可以让它开慢点，不能让刹车阈值变松。

契约细节见 [层间信号契约](../interfaces.md)，字段定义见 [`contracts/`](https://github.com/Peng-EA/embodied-autonomy-stack/tree/main/contracts)。

## 4. 和"Agent 套壳"的区别

| | Agent 套壳路线 | 本项目 |
|---|---|---|
| 谁做决策 | LLM 每一步 | LLM 只做语义规划（L4），实时在 L1–L3 |
| 断线后 | 停住或胡来 | L4 降级，L1/L2 继续维持 |
| 需求从哪来 | 用户 prompt | L1 稳态偏离独立生成 |
| 安全由谁保证 | prompt 约束 | L2 硬否决，与情绪/规划无关 |
| 验证方式 | demo 视频 | 基线对比 + 可复现日志 |

两边不冲突：这套东西是给 LLM **划边界、找位置、解放它**，不是替代它。

## 5. 可证伪预测（这是本文最重要的部分）

如果一个假说不能说明"什么结果会推翻它"，它就不是架构，是信仰。
所以我用四个基线把它钉死（定义见 [评价体系](../evaluation.md)，配置在 [`evals/baselines/`](https://github.com/Peng-EA/embodied-autonomy-stack/tree/main/evals/baselines)）：

| 如果假说**成立**，应该看到 | 如果假说**错了**，会看到 |
|---|---|
| **B1**（有稳态/抢占）断线后仍能继续跑完阶段 1 | 断线后和 B0（全经 LLM）一样停住 |
| **B2**（有需求、无抢占）比 B1 明显更晚满足需求 | B2 与 B1 无差别 → 抢占机制是装饰 |
| **B0p**（有情绪但不调制行为）与 B1 有可测差异 | 两者无差别 → 情绪只是日志里的装饰 |
| 抢占正确率（反事实口径）显著高于 0.5 | 抢占大多是误抢 → 抢占权该收回上层 |

**已经跑出来的、支持假说的第一组数据**（`sim/`，10 秒闭环，单障碍物）：

| 基线 | 结果 |
|---|---|
| B1 | 到桩充电，最终电量 ≈30.5%，抢占正确率 1/1（反事实） |
| B2（无 L1 抢占） | 同样到桩，但**晚约 2 秒**，最终电量 17.6% |
| B0（全经 LLM） | 没有需求来源，只会空转巡逻，**从未去充电** |
| B1 + 强制断 LLM | 走降级路径，仍到桩（27.1%） |

这些数字不大，但方向是假说预测的方向。**注意：这不是结论，是 10 秒、单障碍物、参数未标定的证据。**

## 6. 已知的薄弱处（我自己先挑出来）

1. **四层是工程隐喻**，不是生物等价声明；"神经系统"这个词很好用，也容易被过度解读。
2. **情绪参数没有标定**：效价/唤醒/支配是连续变量，但取值范围和衰减常数都是起点值。
3. **抢占只在仿真里验证过**：单障碍物、静态、无传感器噪声。"真实场景里抢占是否还正确"目前没有数据。
4. **B0 的实现很粗糙**：把它做成"没有 L1 所以没需求"，其实是把对照做成了稻草人。更公平的 B0 应该是"LLM 也能读电池状态"。
5. **没有和现有工作做系统对比**：这一层需要真实的文献阅读与引用（「与现有工作的差异」一节仍标着待补）。

## 7. 所以，现在该做什么

如果你想反驳这篇文章，最省力的方式是**跑一遍 `sim/`，把某个基线改到能让假说失败**：

```bash
git clone https://github.com/Peng-EA/embodied-autonomy-stack.git
cd embodied-autonomy-stack
python -m venv sim/.venv && sim/.venv/Scripts/python -m pip install -r sim/requirements.txt
sim/.venv/Scripts/python -m sim.main --baseline b1
sim/.venv/Scripts/python -m sim.main --baseline b2
```

改 `evals/baselines/*.yaml` 或 `sim/config.py` 里的阈值，看结论是否翻转。
结论翻转了，请开 Issue——**负结果同样是我们想要的东西**。
