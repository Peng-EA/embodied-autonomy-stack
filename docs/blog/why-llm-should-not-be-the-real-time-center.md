# 为什么 LLM 不应成为具身智能的实时控制中心？

**一个可检验的架构命题**

> 状态：观点文章（**初稿**） · 2026-11-06 · 作者 Peng-EA
>
> 文中引用的数字已逐条标注核实状态（见文末附录）：标「已核实」的附了可点开的来源，标「待核实」的尚未逐条对照原文。
> 本文属假说，不是结论；第 6 节给出了"什么结果会推翻它"。

---

## 摘要

当前主流 VLA 在真实控制回路中的频率，在部署条件下常见落在个位数到约 10 Hz 的区间，而接触丰富操作所需的底层控制回路通常在 50–1000 Hz。这一差距常被表述为"模型还不够快"。本文想讨论的是一个不同的解释：**差距的一部分来自架构层面的错配——慢速语义推理与实时控制环在时间尺度上的结构差异——而非仅仅来自算力或工程优化**。如果这一解释成立，那么把 LLM/VLA 主干放在控制环中心就不是一个可以通过"等下一代硬件"解决的设计选择。

需要先划清命题边界：本文**不主张**端到端 VLA 在任何任务上都不该用，而主张在需要独立稳态维持、断线存活或接触丰富力控的任务中，同步回路中的 LLM/VLA 主干会表现出系统性的架构脆弱性。本文梳理可复核的频率数据，分析错配的几种机制，讨论工业界双系统/分层架构对这一问题的回应方式，最后给出一个可证伪的对比框架，供实验检验。

## 一、频率数据：一个需要先核实的起点

讨论"LLM 控制机器人太慢"时，容易滑向模糊的体感判断。先把可查的数字列出来，并标明各自的条件。

RT-2 最大的 55B 模型通过多 TPU 云服务运行，报告的控制频率为 1–3 Hz。OpenVLA（7B，自回归 token 生成）在 RTX 4090 上的推理频率约 5–6 Hz，单步延迟约 170–200 ms。Octo 作为基于扩散策略的通用策略，控制频率依具体配置而定，通常在 2.5–10 Hz 区间。π0.5 部署在 NVIDIA Jetson Orin 上时，一次完整推理约 1.4 秒，对应约 0.7 Hz；经过异步推理与调度优化后，同一硬件上可提升至约 6 Hz。

这些数字不是同一把尺子量出来的：有的跑在云端 TPU，有的跑在桌面 GPU，有的跑在机载边缘设备；有的测的是单次前向延迟，有的是含动作块执行的有效频率；有的模型是自回归 token 生成，有的用扩散或流匹配并行生成动作。把它们并置时应当保留这个限定。尤其要避免一个隐含推论：把"自回归 VLA 慢"直接等同于"所有 VLA 都受同一种慢的约束"。下文的机制分析会区分哪些错配来自自回归范式，哪些来自更普遍的架构位置问题。

另一端的需求侧相对清晰。接触丰富操作——轴孔装配、表面擦拭、力控装配——通常需要 500–1000 Hz 的控制回路来维持稳定；即便高层轨迹规划，也需要 10–50 Hz 的更新率来响应动态障碍。

有工作将这两端的比值定义为 Inference–Control Discrepancy（ICD）：任务所需控制频率与 VLA 可达推断频率之比。这个概念的价值在于把一个模糊的"慢"转化为一个可以随任务和硬件变化的量。但它本身不预设结论：ICD 大，既可能意味着"换更快的模型"，也可能意味着"换模型在系统中的位置"。区分这两种解释，需要看错配的来源。本文的命题属于后一种解释，但它只主张后者是至少一部分错配的来源，而非全部。

## 二、错配从哪里来：三种可能的机制

如果把问题仅仅归因于"模型参数量大"或"GPU 不够快"，那么随着硬件进步，错配应当持续缩小。但至少有一部分错配来自更底层的机制，不随单次推理速度线性消失。以下三种机制按"是否依赖特定动作生成范式"排序：第一种是自回归 VLA 的放大器，后两种对更广的 VLA 家族成立。

**第一，自回归解码的串行结构（放大器，非必要条件）。** 以 RT-2、OpenVLA 为代表的 VLA 将连续动作离散化为 token，再逐个自回归生成。每一个 token 依赖前一个 token，这个串行依赖在解码步之间引入了不可并行的延迟。即使单步前向计算被加速，token 序列的长度和串行性仍然构成一个下限。并行化解码可以缓解这一问题，但缓解的上限受序列长度和动作块长度的共同约束。

需要明确的是，这一机制不是本文核心命题的支柱。π0 用流匹配、RDT-2 用扩散、Fast-in-Slow 的 System 1 也不依赖 token-by-token 自回归解码，这些方法在"生成一个动作块"的层面并不受串行性约束。它们仍然受错配影响，但来源更接近下面两种机制。换句话说：**自回归串行性让错配更严重，但即使换用并行生成动作的 VLA，只要主干仍在同步控制环中以语义编码频率运行，错配仍然存在。** 把这一点说清楚，反而让命题更强，因为它不再绑定某一种动作生成范式。

**第二，语义更新频率与控制更新频率的尺度分离。** Leap-VLA 的工作指出，场景语义的变化大致在 1 Hz 量级，而反应性控制需要 20–50 Hz。这意味着在每个控制步都用数十亿参数的 VLM 重新编码完整观测，大部分算力消耗在"和上一步语义上几乎相同"的画面上。Gemini Robotics 的混合架构提供了一个佐证：云端 VLA backbone 的查询—响应延迟约 160 ms，加上本机 action decoder 的延迟，端到端约 250 ms；有效控制频率 50 Hz 来自 action chunk 的异步展开，而不是 backbone 本身以 50 Hz 运行。

**第三，grounding 的验证成本与控制环的时序保证之间的张力。** 即使语义层面"理解正确"，从语义指称到当前帧像素坐标、再到可行抓取位姿、再到关节力矩约束下的安全执行，这一连串映射需要一个独立于语义推理的快速校验环节：当前帧里目标是否仍在该位置、当前力交互状态下该位姿是否仍可达、执行器是否仍有余量。这个校验不是"再问一次 LLM"，而是一个可以在毫秒级完成的几何/动力学一致性检查。问题在于，当 LLM/VLA 主干位于同步控制环中心时，这个校验环节要么被塞进同一次推理（拉长延迟），要么被省略（留下未验证的执行）。Princeton 的 System-1/2 安全自主性工作将这一点表述为：语义模型的输出需要在真实机器人系统上被可靠地 grounding、定位和执行，而瓶颈恰恰在这一环节。这不是说 LLM 的语义输出"错"，而是说从"知道抓杯子"到"在当前帧、当前力状态下安全地执行这个抓取"之间，存在一个验证成本，而该成本的时间尺度与控制环不匹配。

这三种机制共同指向一个更窄的命题：**错配的至少一个重要来源是架构性的，而非纯粹算力性的。** 这个命题可以被检验：如果它成立，那么即使把当前 VLA 的推理速度提升一个数量级，在不改变系统位置的前提下，它在接触丰富任务中的控制频率仍然会受制于语义—控制尺度分离和 grounding 验证环节的结构性成本。

## 三、错配在系统层面的表现

频率数字本身只是症状。更值得关注的是它在真实系统中对应的几种失效方式——这些失效在第二篇草稿中被较系统地展开，可以作为架构讨论的操作性抓手。

**执行窗口内的开环。** VLA 的典型部署方式是推理一次、输出一段动作块、执行完毕再推理下一次。在动作块执行期间，机器人对新的外界变化处于开环状态。如果推理延迟 200 ms、动作块覆盖 1 秒，那么每一秒中有相当比例的时间，机器人依据的是"上一次观测时的世界"。异步推理可以隐藏部分延迟，但会引入感知—执行错位：推理开始时采集的图像，在动作真正执行时已经过时。

**没有独立的稳态层。** LLM/VLA 的输入通道里通常不包含"机器人自身正在发生什么"的结构化信号：关节温度、电流积分、执行器负载历史、任务进度偏离。这些量不是语义理解的对象，而是内感受层面的监测对象。一个只靠 LLM 规划的系统可以在语义上正确地继续执行任务，同时物理上把自己推向热极限或电量耗尽，而 LLM 不会"注意到"这一点——不是因为它不聪明，而是因为这个信号不在它的输入里。

**断线即失去降级路径。** 如果所有行为决策都经过一个异步外部服务，那么该服务超时、限流或网络中断时，系统没有独立于它的基本行为维持能力。这不是假想场景；云端推理的延迟抖动在部署中是常态。一个可靠的具身系统需要能够在 LLM 不可用的条件下维持基本安全和基本需求满足。行为树基线能做到这一点，不是因为行为树"更智能"，而是因为它不把实时回路绑在一个异步服务上。

## 四、工业架构已经在做什么

2025–2026 年的双系统/分层 VLA 工作，可以读作对上述错配的一系列架构回应——尽管这些工作本身通常不以"LLM 不该控制"作为表述框架。

Figure Helix 的结构是 S2（7B VLM，7–9 Hz 慢推理）加 S1（80M 参数，200 Hz 高频控制），两者通过潜在向量通信。π0 用流匹配将动作生成推到 50 Hz，但 VLM 主干本身并不运行在 50 Hz 的控制环频率上；50 Hz 来自动作生成路径的专门设计。Fast-in-Slow 将 System 1 执行模块嵌入 VLM-based System 2 内部、部分共享参数，在 action chunk 设为 8 时达到 117.7 Hz 控制频率，同时在仿真中平均成功率高出此前 SOTA 8%、真实任务高出 11%。该论文对动机的表述是直接的：基于互联网规模预训练 VLM 的基础策略受益于常识推理，但 "often suffer from low execution frequency"，因此需要将 System 1 从 System 2 中解耦。

REA（Routed Embodied Agent Runtime）则把这个原则提炼成了一条运行时规则："no running policy waits on the brain"——任何正在执行的控制策略不应被阻塞等待上层审慎模块返回结果。在 LIBERO-Pro 的 3000 个测试回合中，REA 报告 95.9% 成功率，高于同策略池中最好的单智能体基线 94.7%，同时控制步数减少 25%、控制时间减少 17%。

这些工作的共同模式值得注意：它们不是在"让 LLM 更快地控制"，而是在把 LLM/VLM 主干从同步控制回路中移出去，让它在异步、较低频率的层级上提供语义先验或任务级条件。这并不构成一个"行业共识"——端到端 VLA 在特定任务上仍然可以很强，且分层本身不是目的，一个调得好的端到端策略完全可能在其适用域内优于一个粗糙的分层系统——但它至少表明，将慢推理与快控制解耦是一个在多个独立工作中被反复选择的架构方向。本文的命题只主张：在需要稳态自主维持、断线存活或接触丰富力控的任务子集上，这种解耦是值得作为基线来对比的设计选择，而不是可选项。

## 五、如果不放在控制环中心，放在哪里？

一个可操作的区分是：LLM 在具身系统中的价值主要在于语义先验、开放词汇理解、任务分解和人机沟通；这些能力对应的时间尺度是秒级到更高级别。实时控制环要求的是毫秒级确定性、稳态维持和硬否决权。把前者放进后者的同步回路里，是用正确的工具做它不擅长的事。

一个以时间尺度为第一性依据的分层可以这样表述：

**L1 内感受/稳态（10–100 ms）**：检测设定点偏离（电量、温度、关节应力、任务进度），产生全局中断信号。这一层不需要语义理解，需要的是确定性和可抢占性。

**L2 反射（10–100 ms）**：避障、平衡、力控、接触修正，对上层输出拥有硬否决权。阈值触发时，任何上层规划——包括 LLM 的输出——被截断。

**L3 动机/调制（0.1–1 s）**：连续内部状态向量调制 L2 的参数（避障距离、探索率、任务优先级权重），生成目标候选。这一层是否需要以及如何工程化，是一个开放问题。

**L4 规划协调（1–10 s+）**：接收目标候选，协调任务分解，调用 LLM 作为外部异步服务。LLM 在这里的主场是语义层面；它不直接产生 L1/L2 时间尺度上的控制量。

关键不在于"四层"这个数字，而在于三条可检验的信号约束：L1 的偏离信号是否具有全局抢占权；L2 的否决是否对包括 LLM 输出在内的所有上层规划一视同仁地生效；L4 在 LLM 不可用时是否有不依赖它的降级路径。如果一套架构在 LLM 断线时不能维持基本安全和基本需求满足，那么问题不在于 LLM 的能力，而在于它在系统中的位置。

## 六、如何检验这个命题

以上论述的核心主张可以压缩为一个可证伪的命题：**在接触丰富或需要稳态自主维持的任务中，将 LLM/VLA 主干放在同步控制环中心，会在延迟抖动、LLM 断线和稳态扰动条件下表现出系统性的失效模式；而将这些主干移到异步 L4、由独立的 L1/L2 回路维持实时安全与稳态，可以在不牺牲语义能力的前提下改善这些条件下的表现。**

本文不预设 B0 一定会失败。如果 B0 在特定任务集上表现足够好，数据会显示出来；如果它在断线或稳态扰动下崩溃，崩溃的方式本身会为架构讨论提供比又一篇"LLM 控制机器人"的演示更具体的信息。负结果同样是有用的结果。在这个问题上，可证伪的失败报告比不可证伪的成功叙事更接近工程判断的可靠来源。

一个有意义的基线集合至少应包括：B0（LLM 中心，所有决策经 LLM，断线即停）；B0′（传统行为树，不依赖 LLM，断线可运行）；B1（保留 L1/L2/L4，移除 L3 调制）；B2（保留需求生成但移除 L1 抢占）。核心指标包括 LLM 断线存活时长、抢占正确率、异常自恢复率，以及"该抢未抢"条件下力超阈值或碰撞事件的发生率。

为了让"可证伪"更具体，可以预设一个判断阈值的示例（具体数值应随任务调整，此处仅示意逻辑）：若在断线后 5 秒内，B0 无法维持任何非零安全动作，而 B0′ 可以维持基本避障与稳态保持，则"位置问题"假设获得初步支持；若 B0 在断线后仍能依靠本地缓存策略维持安全动作超过 30 秒，则说明该实现已经把降级路径内建，本文的命题需要收窄到未内建降级路径的系统。阈值不写死，但给出示例能让对比框架从"原则上可检验"落到"下一步怎么测"。

## 七、本文命题与一个具体实现的关系

上面这个命题需要一个可运行的实现来接受检验。笔者维护的开源仓库 [embodied-autonomy-stack](https://github.com/Peng-EA/embodied-autonomy-stack) 是这个命题的一个具体实现尝试，目前处于 **v0.1 设计草案**阶段（契约仍是草案，`sim/` 下的 MuJoCo 最小闭环已经能跑）。它与本文的对应关系是直接的：

- 本文第三节的"**没有独立的稳态层**"，对应仓库的 **L1 内感受/稳态层**（10–100 ms，检测设定点偏离并拥有全局抢占权）；
- "**断线即失去降级路径**"，对应 **L4 规划协调层**把 LLM 定义为可插拔的外部异步服务——仓库里已经实现降级路径并做过注入测试（强制断线后仍能到桩，只是速度打折）；
- 第二节的"**grounding 验证成本**"，对应 **L2 反射层**对包括 LLM 输出在内的所有上层规划拥有硬否决权；
- 第六节的 **B0 / B0′ / B1 / B2** 基线集合，已经在仓库的 [`evals/baselines/`](https://github.com/Peng-EA/embodied-autonomy-stack/tree/main/evals/baselines) 里以配置形式存在，`sim/` 直接读这些 yaml 跑对照。

| （本文未展开）对照是否公平 | `evals/` 的 B0 | **开放问题**：现在的 B0 被关掉了 L1、等于没有需求来源，是稻草人 |

这些开放问题在仓库里以开放问题的形式保留（见 [ADR-0003](https://github.com/Peng-EA/embodied-autonomy-stack/blob/main/docs/adr/0003-baseline-definitions.md)），而不是以已解决的形式呈现。

**目前跑出来的第一组数据**（10 秒闭环、单障碍物、参数刚标定、每组 1 次，只能算方向性证据）：全系统配置到桩充电，最终电量 ≈30.5%；关掉 L1 抢占（B2）后仍能到桩，但电量 ≈17.6%、晚约 2 秒；没有稳态层的配置（B0）根本没有需求来源，只会空转巡逻，**从未去充电**。抢占正确率按"若没抢、1 秒内会不会撞"的反事实口径算是 1/1。

本文的命题如果成立，仓库的基线对比应当能显示出来；如果不成立，仓库的负结果同样会被记录。**欢迎对命题本身或实现方式提出反驳**——最省力的方式是跑一遍 `sim/`，把某个基线改到能让命题失败。
