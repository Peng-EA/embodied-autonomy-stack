# 路线图

> 状态：草案 · 最后更新 2026-11-05

原则：**每个版本只有一个核心问题**。版本号不是进度条，是"这一版证明了什么"。

## 总览

| 版本 | 核心问题 | 优先级 | 状态 |
|---|---|---|---|
| v0.1 | 这套分层能不能在仿真里跑起来一个闭环？ | MUST | **进行中**（骨架已跑通，契约未定稿） |
| v0.2 | 换栈之后，**公平 B0 + 延迟扫描**能不能跑出可复核的数据？ | MUST | **已跑通（含阴性结果）** |
| v0.3 | 需求能不能**自主**产生，而不是被写死？ | MUST | 未开始 |
| v0.4 | 出错了能不能自己修，抢占是不是对的？ | MUST | 未开始 |
| v0.5 | 能力会不会随时间增长？ | SHOULD | 未开始 |

## v0.1 概念与仿真骨架（MUST）

目标：仿真里跑通**阶段 1（解决自身需求）**的最小闭环。

- [ ] 架构文档与接口契约定稿（本仓库当前状态 → 定稿）
- [ ] 内感受 / 情感变量定义（变量清单 + 设定点区间）
- [ ] 多时间尺度调度器骨架（L1/L2 实时，L3/L4 异步）
- [x] 仿真最小闭环 demo（阶段 1）—— **骨架已跑通**（`sim/`，B1 基线 10 秒闭环），参数未标定

**完成的判定**：给定"电量跌破 25%（`sim` 里从 28% 起跑）"，系统在无外部指令下自主前往充电点并完成充电；
全过程有可解析的日志，能算出"需求驱动行为占比 > 0"。

> 当前实测：B1 基线 10 秒内到桩、需求驱动占比 0.50、抢占正确率 1/1（反事实口径）。
> 判定口径与实测数据都以 `sim/` 为准；本文件只写目标，不抄数字。

## v0.2 换栈 + 公平基线（MUST）· 已完成首轮

目标：把"能不能被第三方复核"从口号变成命令。

- [x] Web 实时栈（`testbed/`，Rapier + Three.js）+ headless 批跑
- [x] 公平 B0（`b0f`：能读电量、能自己决定充电）
- [x] 延迟是参数（0.1–2.0 s），每格 n≥10，报 Wilson 区间
- [x] 确定性：同 seed 同 `stateHash`
- [x] 静态对照组（S1）三条基线打平——台子不偏袒

**首轮结论（阴性）**：移动目标场景下，严格 age 丢弃在 2 s 延迟时 0/20，
照旧执行 20/20。详细区间与局限见 [`evals/v0.2/README.md`](../evals/v0.2/README.md)。

- [ ] `revalidate` 策略（过期但当前感知安全 → 采纳）
- [ ] 移动障碍场景（让"过期"真的危险）
- [ ] 抢占触发条件的构造（本版一次都没触发）

## v0.3 需求与动机（MUST）

- [ ] 稳态偏离检测与优先级生成（`severity` → `goal_candidate.priority`）
- [ ] 内在动机探索策略
- [ ] LLM 接入与边界对比实验（B0 vs B1）

**完成的判定**：能产出 B1 基线的第一份可复现数据，并公开原始日志。

## v0.3 执行修正与成果检测（MUST）

- [ ] 失败检测与重试 / 换策略 / 降级
- [ ] 抢占正确性评估（"该抢"判定 + 人工复核）
- [ ] 真机或高保真仿真验证（SHOULD）

**完成的判定**：注入 20 次失败后，异常自恢复率与抢占正确率均有数据，且方法可被第三方复跑。

## 阶段边界

| 阶段 | 内容 | 何时做 |
|---|---|---|
| 阶段 1 | 解决自身需求（电量、过热、卡死） | v0.1–v0.3 全部 |
| 阶段 2 | 发现并解决程序/LLM 规划外的需求 | v0.4 起，之前只留观测钩子 |

一个连自己电量都不会管的机器人，不可能可靠地发现你没说出口的需求。**先把阶段 1 做扎实。**

## 不承诺的事

- 不承诺时间表。这是个人维护的草案项目，版本号只表示顺序，不表示日期。
- 不承诺每个版本都有"能看的东西"。v0.2 的产出可能只是一份对比数据。
