# 路线图

> 状态：草案 · 最后更新 2026-11-05

原则：**每个版本只有一个核心问题**。版本号不是进度条，是"这一版证明了什么"。

## 总览

| 版本 | 核心问题 | 优先级 | 状态 |
|---|---|---|---|
| v0.1 | 这套分层能不能在仿真里跑起来一个闭环？ | MUST | 未开始 |
| v0.2 | 需求能不能**自主**产生，而不是被写死？ | MUST | 未开始 |
| v0.3 | 出错了能不能自己修，抢占是不是对的？ | MUST | 未开始 |
| v0.4 | 能力会不会随时间增长？ | SHOULD | 未开始 |

## v0.1 概念与仿真骨架（MUST）

目标：仿真里跑通**阶段 1（解决自身需求）**的最小闭环。

- [ ] 架构文档与接口契约定稿（本仓库当前状态 → 定稿）
- [ ] 内感受 / 情感变量定义（变量清单 + 设定点区间）
- [ ] 多时间尺度调度器骨架（L1/L2 实时，L3/L4 异步）
- [ ] 仿真最小闭环 demo（阶段 1）

**完成的判定**：给定"电量从 60% 掉到 10%"，系统在无外部指令下自主前往充电点并完成充电；
全过程有可解析的日志，能算出"需求驱动行为占比 > 0"。

## v0.2 需求与动机（MUST）

- [ ] 稳态偏离检测与优先级生成（`severity` → `goal_candidate.priority`）
- [ ] 内在动机探索策略
- [ ] LLM 接入与边界对比实验（B0 vs B1）

**完成的判定**：能产出 B1 基线的第一份可复现数据，并公开原始日志。

## v0.3 执行修正与成果检测（MUST）

- [ ] 失败检测与重试 / 换策略 / 降级
- [ ] 抢占正确性评估（"该抢"判定 + 人工复核）
- [ ] 真机或高保真仿真验证（SHOULD）

**完成的判定**：注入 20 次失败后，异常自恢复率与抢占正确率均有数据，且方法可被第三方复跑。

## v0.4 发育式能力增长（SHOULD）

- [ ] 能力边界探测与学习进度驱动
- [ ] 发育曲线评估
- [ ] 阶段 2 入口钩子

## 阶段边界

| 阶段 | 内容 | 何时做 |
|---|---|---|
| 阶段 1 | 解决自身需求（电量、过热、卡死） | v0.1–v0.3 全部 |
| 阶段 2 | 发现并解决程序/LLM 规划外的需求 | v0.4 起，之前只留观测钩子 |

一个连自己电量都不会管的机器人，不可能可靠地发现你没说出口的需求。**先把阶段 1 做扎实。**

## 任务 → Issue 映射

开 Issue 时用这些标签，方便别人筛：

| 任务 | 标签 |
|---|---|
| 变量清单 / 设定点 | `interoception` |
| 调度器骨架 | `real-time` `architecture` |
| 情绪向量与调制 | `affect` |
| 目标候选与优先级 | `motivation` |
| 失败检测与降级 | `execution-monitor` `outcome-detection` |
| 抢占正确性 | `outcome-detection` `safety` |
| 契约定义 | `interface-contract` |
| LLM 边界实验 | `llm-boundary` |
| 仿真 | `sim` |
| 入门任务（补文档、画图） | `good-first-architecture` |

## 不承诺的事

- 不承诺时间表。这是个人维护的草案项目，版本号只表示顺序，不表示日期。
- 不承诺每个版本都有"能看的东西"。v0.2 的产出可能只是一份对比数据。
