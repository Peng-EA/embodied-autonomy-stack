# ADR-0006: 推理端点外置为配置，单机只是"端点在本机"的特例

- 状态：已接受
- 日期：2026-11-06

## 背景

L4 的语义规划与 L2 的视觉策略都要调用模型服务。最早一版把地址写成
`http://127.0.0.1:11434`，于是：

1. 第二台机器（RTX 3050Ti 笔记本）要参与测试时，只能改代码；
2. "单机"和"跨机"变成两条代码路径——而跨机才是验证**网络超时/拒连**这一层的地方；
3. 断网测试无法只改配置复现。

## 决策

端点（`base_url` / `model` / `timeout_ms` / `num_gpu`）全部外置，优先级：

```
命令行 --l4-url / --l4-model / --l2-url / --l2-model
  > 环境变量 EA_L4_URL / EA_L4_MODEL / EA_L2_URL / EA_L2_MODEL
  > evals/endpoints.yaml（入库，只含占位地址与模型名）
  > 内置默认（127.0.0.1:11434）
```

配套三条运行时策略：

1. **超时不重试**（重试=新一代请求，会增加一次 2–5 s 的无效占用）；
2. **连接错误重试一次**（跨机首包丢失是常见的，重试一次足矣，记 `endpoint_retry`）；
3. **端点挂了不是启动失败**：L4 记 `connection`/`timeout` 并让在途计划作废；
   L2 回退 scripted。除非显式 `--require-endpoint`，否则进程继续跑。

## 后果

### 正面

- 单机/跨机共用一条路径：`--l4-url http://192.168.2.x:11434` 之外没有任何分支。
- 断网可复现：把端点指到已关闭端口，就能稳定复现 `ConnectionError`（实测 10 次请求里
  7 次拒连，物理环照常 100 Hz）。

### 负面（必须写）

- 配置入口变多（CLI / env / yaml），"我到底连的是哪台"需要 `preflight` 来回答；
  因此 `sim/vla/preflight.py` 不是可选项，而是这条决策的配套义务。
- 跨机时 `timeout_ms` 的直觉会错：L2 的 400 ms 在局域网抖动下更容易触发回退，
  回退率高不等于模型差——报告里必须把"回退率"与"模型质量"分开说。

## 被否掉的方案

- **硬编码两台机器的地址**：换网段、换机器就废；而且会把内网 IP 写进公开仓库。
- **用环境变量一条路走到黑**：临时改一次也要 export，不方便做矩阵实验。
