# ADR-0004: L1 只实现 homeostatic 分支，allostatic 暂不做

- 状态：已接受（**同时登记为已知缺口**）
- 日期：2026-11-06

## 背景

内感受框架（Candia-Rivera 2026，[arXiv:2604.24527](https://arxiv.org/abs/2604.24527)）把内感受调节拆成三条功能原则：

| 原则 | 计算角色 | 本仓库 L1 的现状 |
|---|---|---|
| homeostatic | 内部生存性调节：维持变量在可行域内 | **已实现**：电量/温度/应力 → `severity` → 广播 |
| allostatic | 基于不确定性的**前瞻性**重评估 | **未实现** |
| enactive | 通过交互主动生成数据 | 不属 L1，与 L3 的探索部分重叠（也粗糙） |

仿真里这个差别是可观察的：一次 10 秒闭环中，电量从 28% 掉到 20% 附近，L1 只在越线后报了一次——它不知道"按当前耗电速率还有多久越线"。也就是说，L1 现在是**纯反应式**的：偏离发生了才出声。

## 决策

v0.1 不实现 allostatic 分支，`homeostatic_broadcast` 契约**不加**预测字段。

理由：

1. **前瞻需要不确定性估计，而当前仿真的噪声是人为设的。** 耗电方差、热模型误差都来自我自己写的随机项，估出来的"不确定性"没有物理含义。把它塞进最底层契约，等于用不可验证的数字支撑一个听起来更高级的架构——正是本项目要避免的事。
2. **动契约会让已有对比不可比。** `contracts/` 是四条基线的共同依赖，按 ADR README 的约定，改语义就要重跑历史数据。
3. **反应式版本已经够撑起阶段 1 的核心主张**——"需求生成独立于 LLM"。allostatic 改善的是提前量，不是这条主张的真假。

## 后果

### 正面

- 契约稳定，B0–B2 的对比保持可比。
- 不引入任何依赖未标定估计的模块。

### 负面（必须写，写不出负面就是没想清楚）

- **L1 的"内感受"是不完整的一半。** 对外表述必须写成"homeostatic 层"，不能写"内感受层"就完事——否则是在用别人的框架给自己的半成品抬价。
- 缺前瞻会让某些场景表现成"刚好卡在边界"：看起来像阈值调得好，其实是**没有余量**。这种"看起来稳"比"明显不稳"更危险，因为它不会触发失败信号。
- 8.2 那张表里 L1 与 L3 的接缝没了依据，现在这条分界线是**约定**，不是推导出来的。

## 被否掉的方案

- **直接加 `predicted_time_to_violation` 字段**：看着便宜，但它把一个尚未标定的估计塞进最底层契约，等于给所有基线一个共同的、未经检验的假设。否决。
- **用固定耗电速率的线性外推**：能算，但它把"不确定性"退化成一个常数，得到的不是 allostatic 而是"更早的 homeostatic 阈值"。那是调参，不是架构。否决。

## 什么时候回来做

需要同时满足：

1. 仿真里有**真实分布**的耗电 / 热负载（不是人为噪声），能给出预测误差的量级；
2. 能用数据说明"提前 N 秒干预"比"越线后干预"在指标上更好——否则 allostatic 只是更贵的反应式。

在这之前，路线图把它记为未完成，不记为"设计中"。
