# ADR-0008: 人形基线单独成档（`g1-full`），不改 `full`

- 状态：已接受 · 日期 2026-11-08

## 背景

在此之前，`sim.main` 只有一个「全开」配置 `full`，而且它**没有 yaml**：它是 `sim/baseline.py`
里的内置常量，`baseline_sha256` 只能打 `n/a`；四条 yaml（B0 / B0′ / B1 / B2）都是它的消融，
且全部是**胶囊身体**。

2026-11-08 `--body g1` 跑通（时间基误差 0.0000%、30 s exit 0，见 [`sim/README.md`](../../sim/README.md) 的 S2 一节），
「同一套 L1–L4 换身体」第一次有数可看。随之出现三个必须当场回答的问题：

1. **G1 的结论要不要归档？** 只在 Issue 里贴一次 30 s 输出，三个月后没人知道那是哪版代码、哪副身体。
2. **写进 `full` 行不行？** 不行。`full` 是胶囊的历史参照，v0.1.0 已冻结（tag 在）；
   往 `full` 上加身体语义＝让已发表的对照结果改解释。
3. **数字怎么报？** 30 s 步行对初始坐标浮点敏感：出生点挪 1e-9 m，`walk_30s` 就从 0.5711
   变 0.5752 m/s。而同一初始状态重跑逐位相同（本次实测 5 次日志 sha256 全同）——
   所以单次数字既不代表一次扰动，也不代表一个分布。

## 决策

1. **新增 yaml 基线 [`evals/baselines/g1-full.yaml`](../../evals/baselines/g1-full.yaml)**：开关逐项镜像 `full`，
   并声明 `body: g1`。它**不是第五条消融**——它什么也不关，是「换身体的参照配置」。
2. **注册 + 硬闸门**：`baseline.FILES` 加 `g1-full`；`main.py` 的 `--baseline` 增加该选项；
   `baseline.declared_body()` 读 yaml 的 `body` 键，**声明了就必须与 `--body` 一致**，否则 exit 2。
   历史用法 `--body g1 --baseline full` 不受影响（那些基线不声明 body，一律不拦）。
3. **n≥5 报分布，且分两组口径**：
   - 第一组：同一初始状态 + 默认 seed 连跑 5 次——实测逐位相同，作用是**证明确定性**；
   - 第二组：跨 seed（7–11）各 1 次——本栈唯一能合法扰动出离散度的旋钮，作用是**给分布**。
   报 mean / min / max / 样本标准差；n=5 只报分布、不报区间（沿用 n<8 不给 95% 区间的规矩）。
4. **三处语义不成立照写 TBD**：`L1.charging`（房间无桩）、`L3.hold_charge`（由前者生）、
   `L2.push`（人形无推通道，逃生走速度层）。不补信号、不改判据、不造一个「看起来正常」的数。
5. **G1 摘要新增「净位移」一行**（`sim/main.py`，只对 `--body g1` 生效，胶囊输出一个字不变）：
   平均速度 × 时长的换算会把「站着不动」算成「走过路」，所以净位移单独测。

## 后果

### 正面

- G1 的 30 s 结论第一次有档案：yaml（有 sha256）+ 分布 + 冻结的原始 JSONL，件件可核对。
- `full` 一个字节没动，v0.1.0 的胶囊对照关系不变。
- 「拿胶囊跑 g1-full」这种混标签被机器挡住（exit 2），不靠人记得。

### 负面（必须写）

- **`checks/validate-contracts.mjs` 的基线期望数从 4 改成 5**。这是长期维护点：以后每加一条基线都要改它。
  这道闸门是故意留的（防基线被误删），代价是「加基线不只是加文件」。
- **两套身体两套数字，读者极易跨身体比**。现在靠三处警告挡：yaml 文件头、`evals/g1-full/README.md`、本 ADR。
  挡不挡得住，不知道。
- **第一组没有信息量**（逐位相同 ＝ n=1）。它是确定性证据，不是稳健性证据；
  真正的稳健性要出生点/参数扰动，那属于改场景真源，本 ADR 不做。
- **第二组的离散度只覆盖 mock LLM 的抽签**，不覆盖出生点浮点扰动，也不覆盖真 LLM 的延迟分布。
  换句话说：这个标准差是「下限估计」，不是系统的真实方差。
- **三处 TBD 让 L1/L3 在 G1 上的读数不可解释**：电量回升到 100% 是假象，谁拿这组数谈「续航」就是错的。
- **仍然没有目标值**：「G1-full 算不算好」回答不了。多一条基线不等于多一个结论。

## 被否掉的方案

- **A. 给 `full` 补一个 yaml**（让「全开」也有文件、也有 sha256）：会让 `full` 同时指向胶囊与任何新身体，
  历史标签漂移。要文件就必须另起名字——那就是本方案。
- **B. 顺手加 `g1-b1` / `g1-b2` 等消融兄弟**：胶囊实测里 L3 的差异只有 0.3 个百分点，
  人形上连「这一档的分布」都刚有；先加消融只会生产一堆无法解释的数。
- **C. 在内置常量里加 body 分支**（`full` + `body` 参数）：又一次「两处事实源」，ADR-0003 已否过一次。
- **D. n≥5 就同 seed 跑 5 次了事**：实测逐位相同，等于 n=1 却假装有分布——那是数据造假。
  保留它只作「确定性证据」，不当作分布。
- **E. 扰动出生点取分布**：出生点是 `sim/env/scene_room.json` 的真源，且 S1c 已加 CI 断言（净空 ≥0.60 m）；
  改它属于场景版本变更，得单独一次决策。

## 如果这个决策是错的，会看到什么

- 若「换身体不该单独立基线」的判断错了：会出现 `g1-full` 与 `full` 的数被人直接比大小，
  且结论翻车（例如「人形效率只有胶囊 1/3」被当成结论写进文档）。
- 若「n≥5 两段口径」不够：以后做的出生点扫描，其标准差应当**大于**第二组；
  如果反而更小，说明离散度不是扰动的锅、是 mock LLM 的锅，口径要改。
- 若 `body` 闸门挡错了人：会有人需要「故意跨身体跑」做对照，却被 exit 2 拦住 → 那就把它降成警告。
