## 两处已知缺陷（引用这些数字前必须读）

### 缺陷 1 · B0 的电量被代码钉死

`sim/main.py` 在 L1 关闭时执行：

```python
l1.battery = max(30.0, l1.battery - 0.02)
```

B0 从 28.0% 起跑，第一步就被抬到 30.0%，此后永远 30.0%。**"B0 会没电"在这套配置里不可能发生**，
所以"B0 不充电"是代码写出来的，不是测出来的。这也是 [ADR-0003](../docs/adr/0003-baseline-definitions.md)
里"B0 是稻草人"的具体形态。

### 缺陷 2 · 日志标签塌缩成 B1 并互相覆盖

`sim/contracts.py` 从 `meta["baseline"]` 取标签，而 `sim/main.py` 从未写入这个键，
于是 `meta.get("baseline", "b1")` 恒为 `b1`；文件名固定、以 `"w"` 打开。
结果：full / b0 / b2 会先后写进同一个 `*-B1-*.jsonl`，后一次覆盖前一次。

**已在 2026-11-06 修复**（meta 写入 baseline；文件名加 `HHMMSS`；以 `x` 模式建文件，冲突就加后缀）。
本目录 `runs/` 是修复后重跑的产物，**数字未变**，只是标签对了。

## 能用来支持什么 / 不能支持什么

| 能用 | 不能用 |
|---|---|
| "这套分层在 MuJoCo 里跑通了一个闭环" | "full 比 B0 好"——B0 被钉死，比了不算 |
| "raycast 与解析式感知的行为差异"（65 mm 口径差导致蹭墙） | 任何"延迟敏感性"结论——延迟硬编码 0.35 s，没有扫描 |
| "情绪调制在本场景净效应 ≈0.3 个百分点"（阴性结果） | 任何显著性或置信区间——每格 n=1 |

## 怎么重跑

```bash
python -m sim.main --baseline full --duration 10 --no-render --log-dir .tmp/rerun
```

复现 tag 本身：`git checkout v0.1.0`。
