# v0.2 实验：延迟扫描 + 公平 B0

> 状态：**第一次正式批跑已完成（含阴性结果）** · 最后更新 2026-11-06

## 这一版想回答什么

> 当 LLM 的计划到达时世界已经变了，"照旧执行"和"按 age 丢弃"哪个更划算？

v0.1 答不了：延迟是硬编码的，B0 还被钉死了电量。
v0.2 把两件事都修成可变量：延迟是参数，B0 换成**能读电量、能自己决定充电**的 `b0f`。

## 怎么复现

```bash
cd testbed
npm install
npm test                    # 确定性 / 过期策略 / 区间估计，8 条
npm run bench -- --scenario stage2-moving --baselines full,b0f,b2 \
  --latencies 0.1,0.35,0.7,1.2,2.0 --seeds 20 --out ../evals/v0.2/results/<日期>
npm run bench -- --scenario stage1-static --baselines full,b0f,b2 \
  --latencies 0.1,2.0 --seeds 10 --append --out ../evals/v0.2/results/<日期>
npm run report -- --dir ../evals/v0.2/results/<日期>
```

产物：`runs.jsonl`（每次一行）、`cells.json`（聚合）、`summary.md`（表）、`curve-*.svg`、`trajectories-*.svg`、`meta.json`。
本目录 `results/2026-11-06/` 是随仓库提交的那一份（360 次运行：300 + 60）。

## 场景

| 场景 | 世界 | 用来测什么 |
|---|---|---|
| `stage1-static` | 静墙 + 静止充电桩 | **对照组**：所有基线都应该打平，用来证明台子没有偏袒 |
| `stage2-moving` | 同一堵墙 + **会移动的充电桩**（x 往复，周期 6 s，振幅 0.9 m） | 计划与执行之间世界变了 |

`stage1-static` 的意义和阴性对照一样：如果在这里某条基线也"赢"，说明台子有问题。

## 结果（n 见附表；区间是 Wilson 95%）

### S1 · 静态：全员打平（控制成立）

3 条基线 × 2 档延迟 × 10 seeds：**全部 10/10**。
0.1 s 时三者到达时间都是 7.03 s；2 s 时 `full`/`b2` 走降级路径 12.19 s、`b0f` 8.94 s。

> 结论：台子不偏向任何一方；差异只可能来自 S2 的时间变化。

### S2 · 移动目标：**严格 age 阈值输了**

| 基线 | 0.1 s | 0.35 s | 0.7 s | 1.2 s | 2.0 s |
|---|---|---|---|---|---|
| `full`（丢弃+降级） | 20/20 · 6.72 s | 20/20 · 6.97 s | 20/20 · 10.31 s | **18/20** · 11.05 s | **0/20** |
| `b0f`（照旧执行） | 20/20 · 6.72 s | 20/20 · 6.97 s | 20/20 · 7.42 s | 20/20 · 7.86 s | **20/20** · 9.61 s |
| `b2`（关抢占） | 同 full | 同 full | 同 full | 同 full | 同 full |

**这是阴性结果，不藏：**

1. 延迟一旦超过 `STALE_AGE_MS`（500 ms），`full` 的每个计划到达时都已过期 →
   连丢 2 次 → **永久降级**到本地状态机；降级路径限速 0.85，追不上 0.94 m/s 的目标点。
2. `b0f` 直接采纳过期计划，靠"到点后再要一次"反复修正；在本场景里它更快也更稳。
3. 也就是说：**"过期就丢"不是免费的**。它在本场景买到的是零收益（没有碰撞、没有危险），
   付出的是一次次作废与降级。v0.1 里"过期指令必须作废"的论断，在这里**不成立**。

### 为什么会这样（解释，不是借口）

S2 里"世界变了"只是**目标点挪了位置**，过期计划的后果是"多跑一段路"，不是"撞上去"。
在这种风险结构下，丢弃重算的期望收益本来就低于直接执行。
要让 age 阈值显出价值，得用**过期会危险**的世界（移动障碍占据通道），那是 v0.3 的排期。

## 已知局限

| 局限 | 影响 |
|---|---|
| Mock LLM 是规则规划器 | 测的是"计划的时延与失效"，不是模型能力 |
| `b2` 与 `full` 数字完全相同 | 抢占在 v0.2 场景里**一次都没触发**（需求出现时没有在途请求）。抢占的净效应仍未测到 |
| 目标点做正弦往复 | 目标会周期性回到原处，对"过期执行"宽容；换单向漂移会更苛刻 |
| 单场景、单速度档 | 不能外推到别的几何 |
| n=20 / n=10 | 比例区间仍然很宽（0/20 的上界是 16%） |

## 下一步

1. `revalidate`：过期但当前感知安全就采纳——本版阴性结果直接指向的修复。
2. 移动障碍场景：让"过期"真的危险。
3. 抢占触发条件：在需求出现的同一 tick 里构造在途请求（或把抢占判据改成"severity 跨越"而非"从 0 起跳"）。
